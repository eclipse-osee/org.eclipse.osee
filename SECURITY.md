# Security Policy

This project follows the [Eclipse Foundation Vulnerability Reporting Policy](https://www.eclipse.org/security/policy/), under which security vulnerabilities are handled in a confidential, responsible, and coordinated manner.

## Supported Versions

Security updates are applied to the most recent release of Open System Engineering Environment (OSEE). Users are encouraged to stay current with the latest release to receive security fixes.

## Reporting a Vulnerability

We encourage you to report vulnerabilities privately, giving us time to remediate before public disclosure. Please do **not** report security vulnerabilities through public issues, discussions, or pull/merge requests.

Instead, use one of the following channels:

1. **Eclipse Foundation Vulnerability Reporting Tracker** (preferred first channel):
   https://gitlab.eclipse.org/security/vulnerability-reports/-/work_items/new?issuable_template=new_vulnerability

2. **GitHub Security Advisories** (secondary channel):
   https://github.com/eclipse-osee/org.eclipse.osee/security/advisories/new

You can also consult the [Eclipse Foundation Security team](https://www.eclipse.org/security/) for general questions about the reporting process.

## Disclosure Policy

When a vulnerability is reported, the project team and the Eclipse Foundation Security team will:

1. Confirm receipt of the report.
2. Investigate and validate the reported vulnerability.
3. Develop and test a remediation.
4. Coordinate the release of the fix and, where appropriate, a public disclosure.

Findings that pose an immediate risk of exploitation will be communicated directly to the project's security team and will only be documented publicly after a fix has been released.
