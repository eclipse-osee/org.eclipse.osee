# Artifact Loading Architecture

## Overview

OSEE has two separate artifact loading paths:

- **Client (IDE)**: `org.eclipse.osee.framework.skynet.core` — loads artifacts into mutable `Artifact` objects with a local cache
- **Server (ORCS)**: `org.eclipse.osee.orcs.db` — loads artifacts into `ArtifactReadableImpl` objects via SQL CTEs

Both paths must correctly track the latest transaction across artifact creation, attribute changes, and relation changes.

---

## Client-Side Loading (skynet.core)

### Pipeline

```
ArtifactLoader.loadArtifactsData(queryId, artifacts, loadLevel, ...)
  │
  ├── AttributeLoader.loadAttributeData(queryId, tempCache, ...)
  │     └── loadAttributesFor(artifact, attributes, historical)
  │           • Iterates all attributes, tracks maxTransaction
  │           • Calls artifact.setTransaction(maxTransaction)
  │
  └── RelationLoader.loadRelationData(queryId, artifacts, ...)
        • Loads LOAD_RELATIONS and LOAD_RELATIONS2 queries
        • Tracks relation transaction_id per artifact in artToTx map
        • After loading, calls setTransactionRecord() for each artifact:
          if (artifact.getTransaction().getId() < relTxRecord.getId())
              artifact.setTransaction(relTxRecord)
```

### Key Files

| File | Package | Role |
|------|---------|------|
| `ArtifactLoader.java` | `framework.skynet.core.artifact` | Orchestrates attr + rel loading |
| `AttributeLoader.java` | `framework.skynet.core.artifact` | Loads attributes, sets initial maxTransaction |
| `RelationLoader.java` | `framework.skynet.core.artifact` | Loads relations, updates transaction if newer |
| `Artifact.java` | `framework.skynet.core.artifact` | Mutable artifact with `setTransaction()` |

### Transaction Tracking (Client)

- `Artifact.transaction` is mutable (`setTransaction(TransactionRecord)`)
- `AttributeLoader` sets it to the max across all loaded attributes
- `RelationLoader` updates it if any relation has a newer transaction
- `getTransaction()` returns the current value (always the latest known)
- `getLastModifiedTransaction()` iterates all loaded attributes to find the max (does NOT include relations — the transaction field already covers that)

## Server-Side Loading (orcs.db)

### Pipeline

```
QueryEngineImpl.loadArtifactsInto(queryData, queryFactory, consumer, numArtifacts)
  │
  ├── selectiveArtifactLoad(queryData, numArtifacts, jdbcConsumer)
  │     │
  │     └── SQL generated by SelectiveArtifactSqlWriter.build()
  │           • artWith CTE: artifact row (art_id, art_type_id, transaction_id from osee_artifact gamma)
  │           • atts CTE: attribute rows (joins attr gamma → osee_txs, optionally → osee_tx_details)
  │           • rels CTE: relation rows (joins rel gamma → osee_txs, optionally → osee_tx_details)
  │           • rels2 CTE: new-style relation rows (osee_relation table)
  │           • fields CTE: UNION ALL of atts + rels + rels2
  │           • Outer SELECT: fields.* with optional max(time) over (partition by art_id) as max_time
  │
  └── jdbcConsumer processes each row:
        • First row for an art_id → createArtifact() (sets initial txId)
        • Attribute rows (attr_id != 0) → putAttributeValue, updateTransactionIfNewer
        • Relation rows (attr_id == 0) → putRelation, updateTransactionIfNewer
```

### Key Files

| File | Package | Role |
|------|---------|------|
| `QueryEngineImpl.java` | `orcs.db.internal.search.engines` | Orchestrates loading, processes result rows |
| `SelectiveArtifactSqlWriter.java` | `orcs.db.internal.sql` | Generates the SQL with CTEs |
| `ArtifactReadableImpl.java` | `orcs.data` | Artifact model with txId and latestTxDetails |

### Transaction Tracking (Server)

Two mechanisms:

**1. `txId` (lightweight, always available)**
- Set initially in `createArtifact()` from first row's `transaction_id`
- Updated via `artifact.updateTransactionIfNewer(txId)` as each row is processed
- For attribute rows: `transaction_id` = the attribute's actual transaction (from atts CTE: attr gamma → osee_txs)
- For relation rows: `transaction_id` = the ARTIFACT's creation transaction (from primary.* = artWith.*), so we also call `updateTransactionIfNewer(suppTxId)` when `IncludeLatestTransactionDetails` is enabled
- Returned by `getTransaction()`

**2. `latestTxDetails` (full record, requires `.includeTransactionDetails()` query option)**
- Contains: txId, author, oseeComment, txType, commitArtId, buildId, time
- Set from the row where `maxTime == timeStr` (the newest row) and `suppTxId` is newer than what's stored
- Returned by `getLastModifiedTransaction()` (falls back to `txId` if not populated)

### SQL Column Semantics in Result Rows

| Column | On attribute rows | On relation rows |
|--------|------------------|-----------------|
| `transaction_id` | Attribute's actual tx (attr gamma → osee_txs) | Artifact's creation tx (from artWith primary.*) |
| `supp_tx_id` | Same as transaction_id (txd joined on attr txs) | Relation's actual tx (rel gamma → osee_txs → txd) |
| `time` | Attribute's tx time (from txd) | Relation's tx time (from txd) |
| `max_time` | Max time across ALL rows for that art_id | Same (window function on fields CTE) |
| `timeStr` | to_char(time) for this row | to_char(time) for this row |

### `IncludeLatestTransactionDetails` Query Option

Enabled by calling `.includeTransactionDetails()` on the QueryBuilder. This:
1. Adds `osee_tx_details txd` join in both atts and rels CTEs
2. Selects `txd.author, txd.osee_comment, txd.tx_type, txd.commit_art_id, txd.build_id, txd.time, txd.transaction_id as supp_tx_id`
3. Outer SELECT adds `to_char(time,?) timeStr, to_char(max(time) over (partition by art_id),?) max_time`
4. Java code uses `maxTime == timeStr` to identify the newest row and populate `latestTxDetails`

### `createArtifact()` (QueryEngineImpl)

Called on the FIRST row encountered for an artifact. Reads:
- `transaction_id` → initial `txId` (artifact's osee_txs entry)
- If `IncludeLatestTransactionDetails` and first row matches `maxTime == timeStr`: also populates `TransactionDetails`
- Constructs `ArtifactReadableImpl` with these values

### Guard Logic for latestTxDetails Updates

```java
if (maxTime.equals(timeStr)) {
   if (artifact.getLatestTxDetails().getTxId().isOlderThan(suppTxId) 
       || artifact.getLatestTxDetails().getAuthor().isInvalid()) {
      // Set all latestTxDetails fields from this row
   }
}
```

- `maxTime == timeStr`: This row IS from the newest transaction
- `getTxId().isOlderThan(suppTxId)`: Allow overwrite if this row has a newer tx than what's stored
- `getAuthor().isInvalid()`: Fallback for initial state (SENTINEL)

## Differences Between Client and Server

| Aspect | Client (skynet) | Server (orcs) |
|--------|----------------|---------------|
| Artifact class | `Artifact` (mutable) | `ArtifactReadableImpl` |
| Transaction field | `TransactionRecord transaction` (fully mutable) | `TransactionId txId` (mutable via updateTransactionIfNewer) |
| Loading order | AttributeLoader first, then RelationLoader | Single pass through unified result set (attrs + rels interleaved) |
| Relation tx source | Separate query (`LOAD_RELATIONS`) with explicit `transaction_id` | `supp_tx_id` column from txd join in rels CTE |
| Full tx details | Not applicable (client uses TransactionManager) | `latestTxDetails` populated from row matching maxTime |
| Cache | `ArtifactCache` (persistent across loads) | Per-query HashMap (no persistent cache) |

## Common Pitfalls

1. **Relation rows carry the ARTIFACT's `transaction_id`, not the relation's.** The relation's actual transaction is only in `supp_tx_id` (server) or read from a separate query (client).

2. **`latestTxDetails` must allow updates from newer rows.** The old "set once" guard (`author.isInvalid()`) prevented relation-only changes from being reflected. The fix compares transaction IDs.

3. **`createArtifact()` uses the first row's data.** If the artifact first appears as an "otherArtifact" on a relation row, it gets the relation row's columns (which have the artifact's creation tx, not the relation's tx).

4. **`max(time) over (partition by art_id)` is correct.** The `fields` CTE unions atts + rels, so the window function correctly considers all rows. Each row's `timeStr` is compared against this max to identify the newest.

5. **Without `.includeTransactionDetails()`**, relation rows have no way to provide their actual transaction ID in the result set. Only `txId` via `updateTransactionIfNewer` from the `transaction_id` column works — but that column on relation rows is the artifact's creation tx. So for relation-only tx detection without the details option, `txId` won't advance. Use `.includeTransactionDetails()` if you need accurate last-modified transaction.
