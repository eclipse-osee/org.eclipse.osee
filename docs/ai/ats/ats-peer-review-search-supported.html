ATS Peer Review Search & Filter

Peer Reviews are workflows, like Team Workflows and Tasks: they have a state machine, assignees, an originator, defects, and reviewer roles. Below is what each reviewer-centric search need can do today, and where work remains. All paths start from the OSEE Navigator.

1. See all my open reviews (by single assigned name) Supported
1.1 My Reviews Supported
How To:OSEE Navigator > My Reviews

The quickest way to see your own open reviews is to go to the OSEE Navigator and double-click My Reviews. This opens every review that is currently assigned to you, in one list. It shows only open reviews on purpose: the moment a review is completed or cancelled it drops off your assigned list, so what remains in front of you is exactly the set of reviews you still have work on. My Reviews is always scoped to you, the logged-in user, so there is nothing to configure — you just open it. This is the everyday "what is on my plate right now" view.

1.2 Action Search Supported
How To:OSEE Navigator > Action Search > Review + Team Definition(s) + User Type = Assignee + User = <select> + State Type = Working

When you want to look at a specific person rather than yourself — for example a lead checking a teammate's open reviews — go to the OSEE Navigator and open Action Search. In the search form, set the work item type to Review, choose the Team Definition(s) you care about, set the User Type to Assignee, pick the person in the User field, and set the State Type to Working so you get only the open ones. Running that search returns all of that person's open reviews on the teams you selected. This is the same idea as My Reviews, but with the user and team chosen explicitly instead of defaulting to you.

1.2.1 Additional Fields

From the same form you can add any of the other available criteria to narrow the results further — for example Version, Change Type, Priority, State Name, Review Type, or specific attribute values. You can also switch the State Type between Working and Completed depending on whether you want the open reviews or the finished ones, so the one form covers both the "open" and "completed" questions.

1.2.2 Saving Search

Once a search is set up the way you want it, you can save it so you never have to rebuild it. Use Save on the search form's toolbar (or Save As to keep the current one and create a named copy) and give it a meaningful name such as "My Team Open Peer Reviews."

1.2.3 Running Saved Search
How To:OSEE Navigator > Saved Searches > <your saved search>

From then on, the saved search is available to re-run at any time directly from the OSEE Navigator under Saved Searches — one click reproduces the exact filter and results without reopening the form.

1.2.4 Sharing Searches On Request

The one limitation today is that a saved search lives with your own account only. It cannot yet be handed to someone else or published for the team — that sharing capability is covered under item 6.

2. See completed reviews Supported
How To:OSEE Navigator > Action Search > Review + User Type = Assignee + User = <select> + State Type = Completed

To see completed reviews, go to the OSEE Navigator and open Action Search. Set the work item type to Review, set the User Type to Assignee, pick the person in the User field (yourself or someone else), and set the State Type to Completed. Running the search returns the reviews that person was responsible for and that have since finished. Note that this works even though a completed review no longer has a current assignee: when you search for completed items by assignee, the search is smart enough to also match people who were assigned at any earlier point in the review's life, so you still get back the reviews you actually worked rather than an empty list.

2.1 Saving & Running Supported

This search can be saved and reloaded exactly the way described in 1.2.2–1.2.3 — Save or Save As on the toolbar, then re-run it from Saved Searches in the navigator. As with 1.2.4, a saved "completed reviews" search still cannot be shared with the team.

3. Reviews I started but have not yet completed Supported

This need is already covered by the assignee searches in items 1 and 2, because in ATS being assigned to a review is the signal that you still have work to do on it. In other words, your My Reviews list (or an Action Search filtered to you as Assignee with State Type Working) is exactly the set of reviews you have started but not yet finished — there is nothing extra to configure.

3.1 Filter by Defect Completion On Request

What this does not do today is filter based on whether the defects themselves are "complete." That would have to be a custom search, because what counts as a "Completed Defect" means different things to different teams, and there is no single definition the tool can apply for everyone. — available on request, with priority and funding.

3.2 Role Completion Un-assigns You Supported

The reason the assignee approach is enough is the role model. Each reviewer is given a role on the review, and being given that role also makes you an assignee. When you finish your part and mark your role complete, the system automatically un-assigns you — and you can also un-assign yourself at any time. As soon as you are off the review it stops appearing in My Reviews and in the assignee-based Action Search (1.1 and 1.2). So the reviews still assigned to you are precisely the ones you have started but not yet completed, with no separate "in progress" flag to track.

4. Reviews where I created defects, the producer resolved them, but I have not closed them Supported

Use the Open Defect Items navigator action to return this set directly. The action first limits the candidate reviews to open peer reviews containing the selected user's defect data, then evaluates the defect details to find resolved but unclosed items.

4.1 Manual Review of Defects Supported
How To:OSEE Navigator > Action Search (as in 1 / 2) > open each review > Defects > complete role > un-assign

The practical way to handle it today is to start from one of your assignee searches (item 1 or 2) to get the reviews you are involved in, then open each review and look at its Defects. From there you can see which of your defects the producer has resolved, decide whether you are satisfied with each resolution, complete your role, and un-assign yourself. It is a per-review manual pass rather than a single filtered list, but it does let you get the answer today using features that already exist.

4.2 Directed Defect Search Supported
How To:OSEE Navigator > Review > My Open Defect Items, or User's Open Defect Items > <select user>

My Open Defect Items searches for the logged-in user's defects. User's Open Defect Items prompts for an active user and runs the same search for that user, surfacing matching defects and peer reviews directly.

Most Desirable — Filter Definition
  1. The review is open
  2. AND
  3. I have created a defect (defect created-by = me, the assignee)
  4. AND
  5. The defect's resolution is complete (resolution has text in it)
  6. AND
  7. I have not addressed or closed it (closed = false)

= Then the review is displayed by the filter.

5. Create custom filters and save as a Review Search Supported
How To:OSEE Navigator > Action Search > set criteria > Save / Save As

You can build your own filter from the OSEE Navigator by opening Action Search (or the Review Search form) and combining whatever criteria you need — work item type, team, assignee, state type, version, change type, review type, attribute values, and so on. When the filter is set the way you want, use Save or Save As on the toolbar and give it a name. The saved filter then appears under Saved Searches in the navigator, so each person can keep a personal library of the review searches they run most often and re-run any of them with a single click.

6. Share Review Filters with team On Request

Sharing a saved filter is not a feature today. The only way one person's review search reaches others right now is informally — through training documents, written instructions, or team communication that describes how to rebuild the same search. There is no shared, team-owned place where a filter can be published once and automatically picked up by everyone on the team. A proper "share with the team" capability would store the filter on a shared item — such as a Team Definition — that teammates could simply load from the navigator, so that a standard set of review searches could be maintained in one place for the whole team. — available on request, with priority and funding.

7. Additional Attributes or Criteria Partially Supported

Beyond the core filters, you can already extend both what you search on and what you see in the results, with one notable exception around defect fields.

7.1 Additional Search Fields Supported

The Action Search form already exposes additional fields for criteria beyond the basics, so in many cases you can tighten a review search using attributes that are already available on the form without any new development.

7.2 Additional Result Columns Supported

Once a search has run, the resulting list lets you add columns to display additional information about each review, so you can bring extra attributes into view and sort or scan on them even when they were not part of the filter itself.

7.3 Defect Fields Not Available On Request

The one gap is that these additional attributes and criteria cannot be the defect fields — things like who created a defect, whether it was resolved, or whether it was closed are not available as search criteria or columns today. Making defect fields available this way — available on request, with priority and funding.
